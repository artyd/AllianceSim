# 004 — Персональный телефон в Mini App: свой календарь, задачи, реальные чаты

- **Status:** in-progress (этапы 1–3 готовы)
- **Commit(s):** —
- **Date:** 2026-10-15

## Intent
Сейчас телефон в мини-аппе одинаковый у всех: задачи и чаты лежат в `localStorage`
(на устройстве, а не у человека), ответы в чате — фейковые (`REPLIES`), календарь —
захардкоженный `WEEK`. Нужно сделать телефон **персональным**: у каждого сотрудника,
вошедшего через Telegram, свои события, задачи и **настоящая переписка с коллегами**,
хранящиеся на сервере и приватные.

## Requirements

### 0. Общие
- Персональный телефон работает **только в Telegram Mini App**. Личность — по
  проверенному `initData` → `employees.telegram_id` (уже есть: `/tg/verify`,
  `verifyInitData`). В веб-версии офиса телефон остаётся демо (как сейчас).
- Пользователь Mini App **без привязанного сотрудника** видит экран «Сначала создайте
  персонажа в боте» вместо персональных приложений.
- **Строгая приватность:** данные видят только участники (автор, получатель,
  участники чата/события). HR-токен (`EDIT_TOKEN`) **не** даёт доступа к чатам,
  задачам и календарям. На экране настроек — короткая заметка о том, где хранятся данные.
- В списках выбора людей (чаты, приглашения, назначение задач) показываются **только
  сотрудники с привязанным Telegram**.
- Таймзона всех напоминаний — `Europe/Kyiv` (`CHECKIN_TZ`).

### 1. Чаты
- **Личные чаты 1:1** с любым привязанным коллегой.
- **Групповые чаты** трёх видов:
  - **Чат отдела** — создаётся автоматически на каждый отдел; состав = сотрудники с
    этим `department` (синхронизируется при смене отдела; выйти нельзя).
  - **Общий чат офиса** — все привязанные сотрудники.
  - **Пользовательские группы** — любой может создать: название, участники;
    создатель может переименовать, добавлять/удалять участников; любой может выйти.
- **Мгновенная доставка** (SSE): новые сообщения, правки, удаления, «печатает…»,
  статус прочтения приходят без перезагрузки. При обрыве — автопереподключение и
  догрузка пропущенного.
- **Прочтение:** ✓ отправлено, ✓✓ прочитано (в группе — «прочитали N»). Счётчики
  непрочитанных на иконке «Чаты» и на кнопке телефона — по реальным данным.
- **Редактирование и удаление** своих сообщений (без ограничения по времени).
  Удалённое отображается как «Повідомлення видалено»; правленое — с пометкой «ред.».
- **Вложения:** фото и файлы **до 20 МБ**. Фото сжимаются на клиенте перед загрузкой.
  Файлы отдаются **только участникам чата** (проверка доступа на сервере, не публичная
  ссылка). Файлы **автоматически удаляются через 90 дней** (`ATTACHMENT_TTL_DAYS`),
  сообщение остаётся с пометкой «Файл більше недоступний».
- **Уведомление в Telegram** от бота: «💬 Нове повідомлення від Івана: <превью>» с
  кнопкой «Відкрити» (открывает Mini App сразу в этом чате). Не чаще 1 уведомления
  в 1 мин на чат, и не отправлять, если получатель сейчас онлайн в этом чате.
  В группах — уведомления можно выключить на чат (mute).
- Фейковые ответы `REPLIES` и приветствия `ensureChat` — **удаляются**.

### 2. Календарь
- Свои события: название, дата, время начала/конца (или «весь день»), место
  (свободный текст или переговорная из плана офиса), заметка, цвет.
- Создание **заметки на день** (без времени).
- **Приглашение коллег:** событие появляется у приглашённых со статусом
  «очікує відповіді»; они могут Прийняти / Відхилити (в мини-аппе и кнопками в боте).
  Организатор видит статусы участников. Правка/отмена события организатором —
  уведомление участникам.
- **Напоминание** за N минут: нет / 10 / 30 / 60 (выбирается на событие, у каждого
  участника своё).
- Повторяющиеся события — **вне скоупа v1**.
- Захардкоженное расписание `WEEK` — **удаляется**.

### 3. Задачи
- Личные задачи: текст, опциональный дедлайн (дата/время), отметка выполнено.
- **Назначение коллеге:** задача появляется у исполнителя; автор видит её в разделе
  «Поставлені мною» со статусом (нове / виконано). Исполнитель отмечает выполнение →
  автору уведомление в бот.
- Редактировать/удалять задачу может автор; исполнитель — только отмечать выполнение.
- Демо-задачи из `localStorage` — **не мигрируются**, удаляются.

### 4. Напоминания и уведомления бота
- ⏰ За N минут до события.
- 📌 Дедлайн задачи: в день дедлайна утром и один раз при просрочке.
- ☀️ **Утренний дайджест** в будни: «Сьогодні: 2 зустрічі, 3 задачі» — объединяется с
  уже существующим check-in сообщением (одно сообщение, а не два).
- 📨 Приглашение на встречу / назначение задачи — с inline-кнопками
  (Прийняти/Відхилити, Відкрити).
- В настройках телефона — тумблеры по каждому типу уведомлений (хранятся на сервере).

### 5. Звонки
- Кнопка «Подзвонити» открывает **Telegram-профиль коллеги** (`https://t.me/<username>`)
  если есть username, иначе `tel:<phone>`; если нет ни того ни другого — кнопка
  неактивна. Имитация звонка и уведомление «вам дзвонили» — удаляются.
- Для этого при `/tg/verify` сохраняем `telegram_username` сотрудника.

- **Out of scope (v1):** аудио/видеозвонки (WebRTC), повторяющиеся события, поиск по
  истории сообщений, реакции/ответы на сообщение, сквозное шифрование, синхронизация с
  Google Calendar, персональный телефон в браузерной версии (Telegram Login Widget),
  доступ HR к переписке.

## Design & decisions

**Аутентификация.** Все новые эндпоинты — middleware `requireTgUser`: заголовок
`X-Telegram-Init-Data` → `verifyInitData` → сотрудник по `telegram_id` → `req.me`.
Нет сотрудника → 403. Для SSE (EventSource не умеет заголовки) — короткоживущий
сессионный токен: `POST /me/session` (по initData) → `token` (HMAC, TTL 12 ч) → `GET
/me/stream?token=…`.

⚠️ **Риск:** `verifyInitData` сейчас без проверки `auth_date` (`maxAgeSec=0`). Для
публичного офиса это было ок, для приватной переписки утёкший initData = вечный доступ.
Решение: для `/me/*` включить окно, например 24 ч, и при 401 просить пользователя
переоткрыть Mini App (проверить, не повторится ли проблема «работало и перестало»).

**Хранение (Postgres, новые таблицы в `api/src/db.js`):**
- `chats(id, kind 'direct'|'dept'|'office'|'group', title, dept, created_by, created_at)`
- `chat_members(chat_id, employee_id, last_read_msg_id, muted, joined_at)` — PK (chat_id, employee_id)
- `messages(id bigserial, chat_id, sender_id, text, attachment_id, edited_at, deleted_at, created_at)`
- `attachments(id uuid, owner_id, chat_id, filename, mime, size, path, expires_at, created_at)`
- `events(id, organizer_id, title, starts_at, ends_at, all_day, place, note, color, cancelled_at, …)`
- `event_attendees(event_id, employee_id, status 'pending'|'accepted'|'declined', remind_min, reminded_at)`
- `tasks(id, author_id, assignee_id, text, due_at, done_at, due_notified_at, overdue_notified_at, …)`
- `notify_prefs(employee_id, messages, events, tasks, digest)` — булевы
- Ничего из этого **не** попадает в `state`/`PUT /layout`.

**Realtime.** SSE в Express (`/me/stream`), в процессе — `Map<employeeId, Set<res>>`
и рассылка событий `message`, `message_edit`, `message_delete`, `read`, `typing`,
`chat_update`, `event_update`, `task_update`. Отправка — обычными POST. Один инстанс
API, поэтому без Redis. Caddy: для `/api/me/stream` — `flush_interval -1`. Догрузка
после реконнекта: `GET /me/chats/:id/messages?after=<id>`.

**Файлы.** `POST /me/attachments` (multipart, лимит 20 МБ) → docker volume
`uploads`. Отдача `GET /me/attachments/:id` с проверкой членства в чате. Ежесуточная
очистка просроченных (cron в API или в боте через API).

**Бот.** Уведомления продолжают идти через существующую очередь `notifications` +
`drainNotifications` (расширить `kind`: `message|event_invite|event_reminder|
task_assigned|task_done|task_due|digest` и добавить `payload jsonb` для кнопок/deep-link).
Кнопки в боте (Прийняти/Відхилити) → бот вызывает API с `EDIT_TOKEN` и `tgId`
(серверный эндпоинт `/bot/act`, доступный только с токеном бота). Deep-link в
Mini App: `startapp=chat_<id>` / `event_<id>` / `task_<id>` → `WebApp.initDataUnsafe.start_param`.
Напоминания: cron в боте раз в минуту → `GET /bot/due-reminders`.

**Frontend (`public/index.html`).** Меняется только модуль телефона (`/* phone
(AllianceOS) */`): приложения `chats`, `calendar`, `tasks`, `calls`, `settings`
переводятся на API, когда `TG.active && TG.me`; иначе — текущее демо-поведение.
Офисный рендер (2D/3D, `state`, `CS`) **не затрагивается**. Не полагаться на
`requestAnimationFrame` — обновление UI по событиям SSE.

## Verification
- Синтаксис-хук на каждом сохранении `public/index.html`; `frontend-review` агент.
- `app-verify` вне Telegram: телефон работает в демо-режиме, **без ошибок в консоли**,
  офис (2D/3D) не сломан.
- Двухпользовательский тест в Telegram (два аккаунта):
  - A пишет B → у B сообщение появляется без перезагрузки (< 1 с), приходит
    уведомление бота, кнопка открывает нужный чат; ✓✓ у A после открытия B.
  - Правка/удаление видны у второй стороны сразу.
  - Файл 15 МБ отправляется; 25 МБ — понятная ошибка; ссылка на файл не открывается
    третьим пользователем (403).
  - Событие с приглашением: у B «очікує», B жмёт «Прийняти» в боте → у A статус обновился;
    напоминание за 10 мин пришло обоим.
  - Задача, назначенная B: у B есть, B отмечает → A получает уведомление.
  - Приватность: запрос чужого чата/задачи с initData C → 403; с `EDIT_TOKEN` → 403.
- Пользователь без персонажа видит экран-заглушку, а не чужие данные.

## Принятые по умолчанию (поменять при необходимости)
- TTL файлов — **90 дней**; правка/удаление сообщений — без ограничения по времени.
- Дайджест — в момент check-in (`CHECKIN_HOUR`, сейчас 09:00), одним сообщением.
- Анти-спам уведомлений о сообщениях — не чаще 1/мин на чат; не слать, если получатель онлайн в чате.
- Окно свежести `initData` для приватных эндпоинтов — 24 ч.
